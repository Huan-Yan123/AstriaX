# AstriaX

**NapCat + AstrBot 多开管理器** —— 一个 Windows 桌面程序，把「装运行环境 → 建实例 → 启动 → 开 WebUI」这一整套流程收进一个界面。

不用记 pip 命令、不用手改配置文件、不用来回切文件夹。装好就能用。

---

## 它解决什么问题

想跑 QQ 机器人，通常要连着解决这些事：

- 装 Python、装 AstrBot 的一堆依赖（还经常卡在编译失败）
- 下载 NapCat、让它注入 QQ、配对 token
- 给每个机器人分配不同的端口，避免互相打架
- 升级版本时担心数据丢了
- 同时跑好几个机器人，还要分清哪个是哪个

AstriaX 把这些做成界面上的几次点击。**每个实例独立目录、独立端口、独立数据**，互不干扰。

## 主要功能

### 运行环境：一条龙装好

| | AstrBot | NapCat |
|---|---|---|
| 分发形态 | PyPI 包 | Shell 压缩包 |
| 靠什么运行 | **内置 Python 3.12**（自动装） | **注入 QQ** 运行 |
| 需要 QQ | 不需要 | 需要（新版 QQNT） |
| 需要 Python | 需要（程序自动装内置版） | **不需要** |

两种环境各装一次，之后创建实例时直接选用。

### 下载：多源 + 自动测速

所有资源都从多个加速源下载。程序会**并发探测各源速度**，自动选最快的那条，而不是死等第一个源超时。

界面上每个源都标着实时的 `可用 xxms` / `不可用`，不可用的源按钮会自动置灰。

### 实例管理

- 新建 / 启动 / 停止 / 删除
- 版本升级与**降级**（数据保留）
- 一键重置账号密码（忘了 AstrBot 的管理员密码时用）
- 手动备份 / 回滚
- 查看实时日志
- 内嵌 WebUI，不用另外开浏览器

### 更新

自带更新检查，从 GitHub Releases 拉取，同样走多加速源 + 测速选源。下载有进度和速度显示。

## 环境要求

- **Windows 10 / 11**（64 位）
- 跑 NapCat 的话，需要本机已安装**新版 QQNT**（怀旧版 QQ 不支持）
- 磁盘建议留 5GB 以上（AstrBot 依赖较多）

不需要预装 Python —— 程序会自己装一份内置的，不碰系统环境。

## 安装与使用

### 1. 安装

下载 `AstriaX-Setup-x.x.x.exe` 双击安装。安装目录可以自选。

> 数据默认放在安装目录下的 `data`，卸载时可以选择是否一并删除。

### 2. 装运行环境

打开程序，进「资源与环境」页：

1. **先装 Python** —— AstrBot 靠它运行。点 Python 那一栏的「安装」。
2. **装 AstrBot** —— 在「下载资源」里点一个可用源（绿色 `可用` 标记）的「下载」，选版本安装。
3. **装 NapCat** —— 同样在「下载资源」里，切到 NapCat 那组，选一个源下载。

> NapCat 不需要 Python，可以只装它。

### 3. 建实例并启动

1. 去「实例」页，点新建，选好类型（AstrBot / NapCat）和刚装好的版本。
2. 点「启动」。状态变成 **运行中** 就是好了。
3. 点「WebUI」进管理面板。
4. 忘记密码就点「看看账密」。

> NapCat 第一次启动会注入 QQ，**需要等十几秒**，期间界面会显示进度。

### 4. 想开第二个机器人

再新建一个实例即可 —— 端口会自动分配，数据完全独立。

## 遇到问题

**先导出日志，再求助。** 日志里有运行环境、版本号、报错原文，绝大多数问题看一眼就能定位。

> 设置 → 日志 → 「导出日志」，会生成一个 zip。

然后带着这个 zip 加官方群 **1077554004** 问一下 —— 群里可能已经有人遇到过，答案也留得住。

### 几个常见情况

| 现象 | 怎么办 |
|---|---|
| 点下载一直失败 | 换个源。界面上灰掉的按钮就是检测到不通的源 |
| 版本列表是空的 | 先装对应的运行环境（AstrBot 需要内置 Python） |
| 启动后 WebUI 打不开 | 等十几秒再点。NapCat 要等注入 QQ 完成 |
| 停止后进程还在 | 再点一次停止。脱链的 QQ 会按端口精确补杀 |
| 装到一半想取消 | 点任务条右侧「取消」，半成品会被清掉 |

## 常见问题

**Q：需要我自己装 Python 吗？**
不需要。程序会装一份**内置**的 Python 3.12，不碰系统里的任何东西。

**Q：NapCat 为什么需要 QQ？**
NapCat 的工作原理是把自己**注入到 QQ 进程里**运行，所以本机必须有一个能用的新版 QQ。怀旧版 QQ 不行。

**Q：能同时跑多个机器人吗？**
能。每个实例独立目录、独立端口、独立数据。

**Q：升级版本会丢数据吗？**
不会。程序先停实例、再换版本，数据目录原样保留。也支持降级。

**Q：数据存在哪？**
默认在安装目录下的 `data`。可以在设置里迁移到别的盘。

**Q：卸载会删掉我的机器人数据吗？**
不会自动删。卸载向导里会问你——默认保留数据，也可以选择一起删除。

## 从源码构建

需要 Node.js 20+ 和 pnpm。

```bash
pnpm install
npm run dev        # 开发态
npm run build      # 只编译
npm test           # 跑测试
npm run dist       # 打安装包
```

打完整的三件套（含内部定制版）：

```bash
npm run dist:3
```
