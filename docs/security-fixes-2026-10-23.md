# 2026-10-23 使用问题与安全边界修复

项目继续采用本地构建、上传源码和安装包的方式发布。已移除 GitHub 工作流配置，并排除依赖、编译输出、安装包、测试数据、临时目录、编辑器配置和 Python 缓存；仓库根的 `latest.json`、源码、打包图标和锁文件继续保留。之前被跟踪的 4 个 Python 字节码缓存已清除。

## 修复内容

| 问题 | 触发与影响 | 修复 |
| --- | --- | --- |
| 主窗口导航与 IPC 来源缺少限制 | 页面跳转后可能继承 preload 权限；非启动器页面可尝试调用文件、进程或凭据接口；新窗口链接直接交给系统会放行危险协议 | 按 WebContents 身份、主框架和精确文档 URL 校验所有生产 IPC；拦截外部导航与重定向；系统浏览器仅接收 http/https 链接；WebUI 使用隔离沙箱且不提供启动器权限 |
| 恢复失败导致当前数据不可用 | 先移走 data，再发生配置目录占用或写盘错误，会留下缺少数据的实例 | 完整暂存后按顶层项替换；任意替换失败自动恢复操作前的数据；恢复失败无法自动还原时保留原件并报告路径 |
| 空目录与不完整备份 | 空库备份未记录目录，恢复时留下后来新增的数据；读取失败被静默跳过，可能生成不完整的“成功备份” | 记录空目录范围；读取失败明确中止；不存在的目标实例目录可重新创建后恢复 |
| 备份路径与恢复范围不够严格 | `data/../instance.json`、Windows 备用数据流、非数据目录等条目可通过原来的边界校验 | 在接触当前数据前检查规范路径、Windows 文件名、重复路径、顶层数据范围和元数据文件形状 |
| 同名更新下载互相干扰 | 并发下载共用 `.part`，后来的请求可删除前一个请求的文件；中断时留下残片 | 每次下载使用独立暂存名，失败清理自身残片；成功后原子替换；校验文件名单段及 Windows 保留名称 |
| 损坏压缩包被当成安装成功 | PowerShell 解压错误可能返回 0，后续写入运行时标记 | `Expand-Archive` 使用终止错误模式，并在移动文件前确认解压结果包含运行时入口 |
| 打不开备份文件夹 | 生产装配没有注入可选的 `opts.openPath`，点击后出现 TypeError | 使用已有的系统默认 `openPath` 适配器，保留路径边界检查 |
| 旧运行时和构建依赖存在已知漏洞 | Electron 实际随应用运行，不能仅因其属于 devDependencies 就略过 | 升级 Electron 和相容的构建、测试依赖，对传递依赖固定修复版本 |
| 新版打包器无法编译自定义安装器 | 自定义进程检查绕过了新版模板必需的 PowerShell 可用性初始化，NSIS 报未知变量 | 在支持该宏的模板中补齐初始化，保留现有退出、数据保护及卸载逻辑 |

Electron 的来源校验和导航限制依据[官方安全指南](https://www.electronjs.org/docs/latest/tutorial/security/)。运行时选用受支持分支中的 Electron 43.8.3；[官方支持策略](https://www.electronjs.org/docs/latest/tutorial/electron-timelines)覆盖最新三个稳定主版本。
