# AstriaX Launcher 0.2.1 开发文档

更新日期：2026-10-08

## 软件用途

AstriaX 是 Windows 桌面启动器，用于管理 AstrBot 与 NapCat 实例。用户可创建多个相互隔离的数据实例，为实例绑定运行时版本，启动/停止服务，在内嵌视图中打开对应 WebUI，并管理凭据、日志、备份和运行时导入。

## 技术结构

- 桌面壳：Electron 主进程负责窗口、IPC、进程生命周期、文件系统和系统集成。
- 界面：Vue 3 渲染进程提供实例卡片、创建向导、下载/导入、设置和备份页面。
- 状态：实例索引与配置位于用户数据根；实例数据与共享运行时分开保存。实例记录的运行时 tag 是版本绑定依据。
- 服务：`src/main/ipc.ts` 是渲染层与主进程业务的边界；`store`、`proc`、`runtime`、`update`、`logs`、`webui` 各目录承载具体能力。
- 打包：Electron Vite 构建，Electron Builder 生成 Windows 安装/便携产物。

## 关键流程

### 启动实例

渲染层发起 `instance:start` → 主进程拒绝搬家期间或重复启动 → 校验实例、NapCat 的 QQ 依赖和端口 → 修复无效端口 → 解析与实例绑定的运行时 → 后台确保 AstrBot Dashboard → 创建子进程并等待目标端口就绪 → 更新状态并记录审计日志。启动失败会反馈具体原因并清理启动锁。

端口连通只代表“有服务”，不证明它属于此实例。因此启动前发现端口已被占用时拒绝再生成进程，避免把旧服务/其他实例误认成本次启动结果。

### 打开 WebUI

主进程先确认实例在当前启动器会话中成功启动（或进程管理器仍确认它运行），再检查端口并创建 WebContentsView，防止未启动的新实例误连复用端口上的旧 NapCat。AstrBot 使用根路径；NapCat 使用 `/webui/`，若实例配置有 token 则 URL 参数经过 URL 编码。视图管理器异步加载后才显示，切换实例会销毁旧视图，同一时刻只保留一个页面，避免旧 NapCat 页面在 AstrBot 页面关闭/加载失败时重新显露；关闭中的加载不能重新挂回窗口，加载超时会清理失败视图。嵌入网页默认缩放到 85%，WebUI 视图外框尺寸不变，以增加首屏可见内容；缩放不影响启动器界面。

### NapCat 停止和删除

NapCat 可能注入到用户 QQ.exe 中，脱离启动器创建的子进程树。停止流程先结束启动器管理的进程，再等待实例端口释放；如果无法证明剩余监听进程属于当前 NapCat，就不强杀 QQ，而是返回可见错误。删除、切换运行时、备份等依赖停止的操作因此中止，保留实例索引与文件，避免端口被新实例复用后错误打开旧 WebUI。用户关闭对应 NapCat/QQ 后可重试。

AstrBot 启动命令同时传入 `--port` 和 `DASHBOARD_PORT`，使 CLI 与 Dashboard 配置都指向实例记录中的端口。这样启动器卡片、内嵌页面和用户复制到浏览器的本机 URL 使用同一端口。

### 备份与更新

实例备份由业务层生成并校验 manifest/hash；覆盖更新的安装器先生成数据备份，应用负责异步列出和保留策略清理。清理仅触及时间戳格式正确且含目标备份包的目录。

## 开发和构建

需要 Node.js 与 pnpm。安装依赖后运行 `pnpm dev` 启动开发窗口，`pnpm build` 构建应用，`pnpm dist` 生成发行包。主进程 IPC 的返回值和预加载通道需与 Vue 页面保持一致。文件删除、目录替换、版本变更应先校验路径与运行状态，并使用暂存目录/原子替换。

## 本版审查范围

逐项审查 WebUI/实例状态、进程启动、端口、备份清理、运行时导入、凭据与主进程同步操作，并做 UI 交互静态走查。0.2.1 已修复的内容和验证状态见 [开发日志](./开发日志-0.2.1.md)。

## 2026-10-08 界面整理

全应用视觉统一覆盖实例、下载/镜像源、备份、设置、创建向导、首次启动和通用弹窗：内容页使用标题层级和分隔线组织信息，实例/备份/镜像源由嵌套卡片改成行式列表，下载进度改为无卡片底色的任务行，并加入透明四帧角色循环动画。设置面板使用双栏分区，窄窗口降为单栏；主导航增加文字标签，窄窗口收回图标栏。Logo 定为颜色参考：界面采用清透冷蓝白底、深钴蓝主操作色和极浅蓝紫辅助色，蓝色用于主要操作、选中态和焦点提示。内嵌 WebUI 缩放到 75%，在固定窗口大小下增加首屏可见内容。

AstrBot 安装速度以 Mbps（十进制 bit/s）显示，方便与 Windows 任务管理器对照；检测到 pip 使用缓存时明确显示本地缓存读取速度。pip 的进度数据来自下载/读取字节，不代表整台电脑网卡的总吞吐。
