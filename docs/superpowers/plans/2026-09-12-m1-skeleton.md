# M1 懒人启动器骨架 实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 可运行的 Electron 桌面应用：SQLite 实例模型、从模板复制创建 AstrBot/NapCat 实例、端口分配、实例启停与状态灯，粉色系骨架 UI。

**架构：** Electron 单进程框架——主进程 Node.js 持有 SQLite（better-sqlite3）+ 实例进程管理器 + 端口分配器，经 IPC 暴露给 Vue3 渲染进程；渲染层只发意图（ipcRenderer.invoke）不直接碰文件系统/进程。

**技术栈：** Electron 33+ / electron-vite / Vue3+TS / JSON 状态文件（决策变更：弃 better-sqlite3，避免原生编译依赖，理由见规格 §3）/ Vitest / electron-builder（M1 只配 NSIS+AppImage 占位）

**规格：** `docs/superpowers/specs/2026-09-12-napcat-astrbot-launcher-design.md`

## 全局约束

- 纯中文界面文案；MIT LICENSE 须存在
- 仅 Windows + Linux 两个构建目标
- 双版本发行：构建变量 `LAUNCHER_EDITION=bundled|pull`，M1 中 bundled 版模板内置、pull 版模板目录可空（首启下载在 M3 做，M1 pull 版允许空白模板但创建时报「模板未就绪」）
- 实例命名规则：AstrBot `a_<id>` / NapCat `n_<id>`，id 为 nanoid
- 默认端口段 6100-6199，分配时探测占用跳过
- 备份默认保留 5 份（M3 才实现备份，端口/设置常量先入库）
- 端口段、数据根等设置存 `<数据根>/config.json`
