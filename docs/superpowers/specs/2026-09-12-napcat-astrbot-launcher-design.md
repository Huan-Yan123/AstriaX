# NapCat + AstrBot 懒人启动器 设计规格

日期：2026-09-12
状态：待用户审查
许可证：MIT

## 1. 概述

一个开源（MIT）桌面管理器，把 AstrBot 与 NapCat 的完整运行环境打包成「装完就能用」的懒人包：多开实例、WebUI 端口分配、内嵌 WebUI、版本检测与更新、自动备份与回滚、密码/token 重置、实时日志。纯中文界面，粉色系柔和二次元风格（圆润、无看板娘角色）。**平台：仅 Windows（用户决策 2026-09-12：放弃 Linux，连带作废 Linux 管理器 WebUI 服务方案）。发行：仅安装包，双版本（离线内置版 / 联网拉取版）。**

工作目录（项目根）：`E:\MX\launcher-acb`（新建仓库，MIT LICENSE，GitHub 开源）。

### 非目标（明确不做）

- 不做管理器自身在线更新（支持保留数据的覆盖安装即可）
- 不检测/不接管用户在 AstrBot 或 NapCat **自身 WebUI 内**执行的更新行为
- 不捆绑 QQ NT 安装包（版权风险），改为引导一键安装
- 不做 macOS 版本
- 不做多语言（纯中文）
- 不做看板娘/吉祥物角色

## 2. 名词约定

| 名词 | 含义 |
|---|---|
| 运行时模板（template） | 安装目录里一份干净的 AstrBot 程序资源（含依赖）或 NapCat 程序资源，本身不运行、不存数据 |
| 实例（instance） | 从模板复制出来的一份独立运行时 + 独立数据目录 + 独立端口，可独立启停、更新、备份 |
| 配对 | 用户手动为 AstrBot 实例选择连接哪个 NapCat 实例（互相在 WebUI 里配连接参数，管理器只提供端口信息） |

## 3. 技术选型

- **框架**：Electron（主进程 Node.js 管全部实例/进程/文件/网络），前端 Vue 3 + TypeScript + Vite
- **内嵌 WebUI**：`WebContentsView`（不是 iframe，不受跨域响应头限制，AstrBot / NapCat 的 WebUI 都可靠嵌入）。用户点击实例卡片 WebUI 按钮后直接在 GUI 内嵌打开
- **实例元数据**：JSON 状态文件（`<数据根>/instances.json` 全局索引 + 每实例目录内 `instance.json`）。选 JSON 而非 better-sqlite3 的原因：避免原生模块本地编译与 Electron ABI 适配问题（部分用户机器无 VS 工具链，会破坏「离线装完即用」的发行目标），打包时也免去 asar unpack。实例数据量小（十级），无复杂查询
- **备份/更新包打包**：Node 原生流 + `tar`（gzip），Windows 回滚兼容
- **打包**：electron-builder → Windows NSIS 安装包
- **进程**：AstrBot = 便携 Python 启动；NapCat = NapCat.Shell 挂载 QQ NT（Windows）

### 目录结构（安装后 & 实例）

```
<安装目录>/                          # 只读资源
  resources/templates/
    napcat-template/                # 干净 NapCat 运行时（含包装脚本）
    astrbot-template/               # 干净 AstrBot 运行时（含 DATA 目录约定）
    astrbot-python-<os-arch>/       # 便携 Python（离线内置版才有；拉取版为空）
<数据根目录 - 用户首次运行选择>/
  instances/
    a_<id>/                         # AstrBot 实例：运行时副本+数据目录混存
      runtime/                      # 从 astrbot-template 复制
      data/                         # AstrBot 数据（配置、数据库、插件）
      backups/                      # 备份包 + manifest
      instance.json                 # 类型、模板版本、端口、创建时间
    n_<id>/                         # NapCat 实例：同构（runtime/data）
  cache/downloads/                  # 更新包缓存（可清理）
  config.json                       # 端口段、备份保留数、镜像偏好、数据根
```

> 为什么「运行时+数据放同一实例目录」：实例是用户心智中的最小单位，整目录拷走/删除/备份都是一次操作；模板只出现一次在安装目录，实例复制时即快照化，后续互不影响。

## 4. 核心流程

### 4.1 首次启动

1. **数据存放位置（用户决策 2026-09-12 再次修订，终版）：所有东西全部安装/存放在管理器同目录、几乎不占 C 盘——安装目录旁固定 `data\`（实例数据、运行时模板副本、备份、日志、缓存都在里面），数据根固定不可调整、不做 GUI 迁移；整个安装目录拷走即用；首启不再询问，只展示一页「数据存这里」告知固定路径**
2. 【联网拉取版】校验本机是否已有模板与便携依赖，缺则进入首启下载（走镜像测速流程，见 4.4）【离线内置版】跳过
3. 生成空实例列表，进入主界面

### 4.2 创建实例

- 选类型（AstrBot / NapCat）→ 命名 → 显示预估磁盘占用（离线版 AstrBot 实例 ≈ 800MB，以实测校准）→ 复制模板 → 写 `instance.json` → 分配 WebUI 端口
- NapCat 实例首次启动前若检测到本机无 QQ NT，弹引导卡（QQ 官方安装包的一键引导安装，装完即注入可用；QQ 本体归系统目录，实例只注入）
- **实现要点：进程级 CPU/内存用 `pidusage`；磁盘占用按时对实例目录做增量扫描（创建/更新后触发），真实尺寸在卡片 hover 时细化；内存/磁盘余量用 `os.freemem/totalmem` 与 `_win32GetDiskFreeSpaceExW`（Windows）**

### 4.3 启停与告知

- 启动实例：spawn 子进程，重定向日志到 `data/logs/latest.log` 与 `backups/` 外的实例目录
- **AstrBot 首次启动**：落定后从其 webui 凭据/日志解析出账号+密码，GUI 中央弹「你的 AstrBot 账号密码」卡片（可复制），仅第一次
- **NapCat 每次启动**：读取运行时内 webui token 配置，MainTray 卡片常驻显示 token（可复制），并显示「扫码登录」二维码卡片（QQ 登录态未Ready时）
- WebUI 按钮：实例未运行 → 置灰；运行中且被 shim 校验端口在监听 → 点亮，点击后 GUI 内以 WebContentsView 嵌入该端口

### 4.4 更新

- **检测**：GUI 启动时全量检测一次 + 手动「检查更新」按钮。数据源 = GitHub Releases 直链 + 多个国内镜像，对每个可用源做 HEAD 测速，用户挑一个，勾选「记住本选择」，下载失败自动回退到下一个可用源
- **更新对象**：用户点实例卡片上的「更新」，或「一键全部更新」；顺序 = AstrBot/NapCat 逐个串行，任一失败即停（后续实例不再更新，不影响已成功者）
- **单实例更新流程**：
  1. 若正在运行 → 优雅停止
  2. 备份：整实例目录（runtime+data）→ `backups/<旧版本号>-<时间戳>.tar.gz` + `manifest.json`（版本、时间、大小、来源）
  3. 下载新版本程序包 → 校验（大小+可选 sha256）→ 替换 `runtime/`（`data/`原地不动）
  4. 启动 + 健康检查（WebUI 端口可达 & 日志无致命错误）
  5. 失败 → 自动回滚到 2 的备份并明确提示
- 备份保留策略：按 manifest 时间倒序保留 N 份（默认 5，可在设置改）；更新包留在本地缓存目录，设置里可一键清理
- 回滚：GUI 显示所有备份（时间/版本/大小）→ 点「回滚」→ 停实例 → 恢复备份 → 启动。回滚后不屏蔽该版本后续提醒

### 4.5 密码/token 重置

- AstrBot WebUI 密码：GUI 里打开实例卡片 → 「重置密码」→ 用 AstrBot 的命令行能力重置凭据 → 弹新密码卡片（可复制）
- NapCat WebUI token：重写该实例 webui token 配置文件为新随机值 → 弹新 token 卡片

### 4.6 托盘与自启

- 关窗最小化到托盘；托盘菜单：显示主界面 / 一键停所有实例 / 退出（退出=停全部实例）
- 开机自启开关（Windows：注册表 HKCU Run），默认关闭

## 5. GUI 设计（粉色系柔和二次元）

- 主题（用户决策修订：放弃二次元粉色）：**克制的中性浅色**——底 `#f5f6f8`、卡片白、主色稳重蓝 `#4a7ddb`（深 `#3861b5`）、语义色：运行=绿 `#34a67c`、停止=灰、错误=红 `#e0645e`；圆角 14px、细边框分隔、无装饰渐变；墨字 `#2f3542`、弱字 `#7a8291`。视觉基调随普通现代软件
- 布局（用户决策 2026-09-12 修订）：**AstrBot 与 NapCat 分属两个独立页面**，左侧窄边栏只放页签（AstrBot / NapCat / 设置）不放新建按钮；每页顶部右侧放**长方形主按钮「新建 AstrBot 实例 / 新建 NapCat 实例」**；页面只列对应类型的实例卡片流（每卡：名称、类型徽章、状态灯、当前版本、**资源占用（每实例：内存 MB、CPU %、磁盘占用 MB，2 秒刷新）**、WebUI 按钮（三态）、启停、更新、备份回滚、更多菜单），右侧/全屏抽屉 = 内嵌 WebUI 与日志面板
- **标题栏：GUI 全接管（用户决策）——frame:false 无系统边框，自绘品牌标题栏 + 最小化/最大化/关闭三键（IPC windowCtl），整条栏可拖动**
- **安装器 UI（用户决策）：与主程序视觉分离，单独设计「小而精简」的安装向导——极简配色、进度友好、默认路径一键改变、完成后弹出首次启动引导；不做二次元大图（那是装完后的主程序的事）。M4 实现时用 NSIS 自定义页落地**
- **空间预检（用户决策 2026-09-12）：安装器在路径选择页展示——①安装包自身所需空间，②含「后续安装的一套 NapCat + AstrBot 运行时模板」的总体预估（二者相加给用户一个大数）；同时读取所选盘剩余空间；剩余空间 < 总体预估 → 拒绝继续安装并明说差多少**
- **卸载与注册表（用户决策 2026-09-12）：**
  - 安装时写入：`HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\ACBLauncher` 卸载信息（UninstallString、DisplayName、DisplayVersion、EstimatedSize）、开始菜单快捷方式、`HKCU\Software\ACBLauncher` 记录安装路径与**当前数据根路径**（数据根会迁移，此注册表值随之更新，卸载器据此找到数据）
  - 卸载时：弹「数据处置」选择页——保留实例数据（默认，只删程序）/ 全部清除 / 备份后清除（导出 zip 到桌面）；数据处置只针对安装目录内 `data\`，另按注册表记录的 installPath 处理
  - 卸载时注册表清理：HKCU 下两条键移除开始菜单项、App Paths

## 4.7b 正常软件完整性清单（工程底线，随里程碑逐步落地）

- 单实例锁（Electron requestSingleInstanceLock；二次点击唤起已有窗口）
- 全局异常处理：main 进程 process.on(uncaughtException) 弹可视化错误卡 + 日志落盘；renderer onError 上报主进程
- 优雅退出：退出前全部实例先停（已有 PM.killAllSync 钩挂 quit 事件）；**清理是白名单式——只杀管理器自己 spawn 并持有 pid 的进程树，绝不按进程名扫描系统（用户另跑的 napcat/astrbot/QQ 一概不碰）**
- 配置/索引防损坏：全部 JSON 均原子写（已实现）；instances.json 损坏时从逐实例 instance.json 自动重建索引并备份坏文件
- 日志：主进程日志滚动保留（7 天/20MB 上限），Diagnosis 一键导出 zip（日志+配置+实例清单，无隐私数据外发）
- 版本与变更：严格 SemVer；「关于」页含版本号与更新日志入口
- 键盘与可访问性：所有交互按钮可 Tab 聚焦，ESC 关弹窗，强制 prefers-reduced-motion 生效
- 隐私底线：不采集任何遥测；更新检测只请求 GitHub/镜像，不携带用户标识
- 语言与文案：全中文、同一动作同一动词（如「启动」贯穿按钮/提示/日志文本）
- 卡片内容：名称、类型徽章、状态灯、当前版本、**资源占用（每实例：内存 MB、CPU %、磁盘占用 MB，2 秒刷新）**、WebUI 按钮（三态）、启停、更新、备份回滚、更多菜单
- 总览（侧栏底部常驻）：**所有实例合计 占用 vs 系统上限**——总内存/可用内存、磁盘总容量/可用容量，接近上限（>85%）时预警变色
- 实现要点：进程级 CPU/内存用 `pidusage`；磁盘占用按时对实例目录做增量扫描（创建/更新后触发），真实尺寸在卡片 hover 时细化；内存/磁盘余量用 `os.freemem/totalmem` 与 `fs.statfs`（Windows）
- 日志面板：逐实例 tab，语义化着色（INFO/WARN/ERROR），支持暂停/导出/清屏
- 设置页：数据根目录、端口段、备份保留数、镜像偏好、开机自启、清理下载缓存

## 6. 数据与错误处理

- 端口冲突：分配时探测占用，冲突跳到下个号；实例启动失败大多为端口被占 → 卡片上给出明确原因
- 进程崩溃/异常退出：卡片红状态 + 日志面板定位到 error 行；提供「查看日志」「重启」快捷入口
- 备份失败（磁盘不足/权限）：中断更新并提示，不清除旧实例
- 全部数据落实例目录，卸载管理器不碰实例数据（卸载时提示保留/删除）

## 10. 「任何 Windows 都能跑」的自包含策略（用户问答 2026-09-12）

- 目标：不需要用户提前装 Python/Node/任何运行时，也不动系统环境变量
- AstrBot 运行时 = 便携版 Python（Windows embeddable package）打进实例 runtime\ 目录，绑定该捆绑 python.exe 启动
- NapCat 运行时随模板携带（M3 模板接线落实实际布局）；Electron 本体已自包含
- 双版本：联网安装版=安装器/首启走镜像下载模板 + SHA256 校验；绿色版=模板直接内置产品目录 templates\
- 模板缺失 → 设置页一键下载模板（镜像列表 + 校验 + 失败重试）

## 11. 托盘与关闭策略（用户决策 2026-09-12）

- 点 ✕ 默认=最小化到托盘，不退出
- 首次点 ✕ 弹一次确认：「最小化到托盘」或「直接关闭」，记住用户选择
- 设置页可改（config `closePolicy: 'tray' | 'quit'`，默认 tray），记住选择后不再重复问
- 退出入口：托盘右键「退出」；will-quit 依旧先白名单杀全部实例
